📖 How this report works

What it shows

Every active part with its current ABC code (from the part) beside the code its usage projects, how much of it was used in the date range, and its unit cost. It is the BI version of the standard ABC Report and reads the same data the same way.

Qty Used is what was shipped on sales orders and/or consumed by work orders in the range (the two Usage options), in the part's own unit.

How the projected code is worked out
  • % of Total = the part's Qty Used ÷ the usage of all parts in the range (inactive parts included, so the column can add up to less than 100%).
  • Parts are taken in Qty Used order, highest first, keeping a running total of % of Total that includes the part itself.
  • A while that running total is under 80%, B while it is under 95%, C from there. The part that takes the total past 80% is already a B. Turn on Cumulative % to see the running total.
  • The thresholds are the standard report's own; Fishbowl has no setting for them. With no usage in the range every part comes out A, as in the standard report.
  • Quantities in different units are added as they are, as the standard report does.
Using it
  • Filter changes apply straight away. The costing method and the layout options only redraw.
  • A projected code shown in colour differs from the part's current code; Only parts whose code would change lists just those.
  • Click a group's row to show or hide its parts; Expand / Collapse do every group. With Show totals on, a group's row carries the sum of its parts' unit costs and of their % of Total, as the standard report's group footer.
  • Click a column heading to sort the parts within each code group (again to reverse, a third time for the standard order). Drag a heading onto another to move the column; drag a heading's right edge to resize it. Your layout is remembered; Settings → Reset column layout undoes it.
  • The Table / Pivot selector switches to a pivot: the number of parts, Qty Used, % of Total, Part Cost or Usage Value (Qty Used × Part Cost) by any two of current code, projected code, part and UOM. Current × Projected shows how many parts move from one code to another. Click a figure to see the parts behind it. Print, PDF and Excel follow the view on screen.
  • The App / PDF buttons in the header switch between this interactive view and the printable pages, laid out like the standard report. In PDF view pick the paper size and orientation in the bar above the pages; they are remembered. Print prints those pages.
  • A very large result shows its 10,000 most-used parts with a Load all button. Their codes are exact; the group totals then cover the parts shown.
